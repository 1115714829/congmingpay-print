### 三轮-1 [WARNING] MQTT connect 排队任务无法被 close 取消（僵尸连接）
- **文件**：`mqtt/MqttClient.kt`
- **问题**：`start()` 只是把 `connect(r)` 排入 executor，destroyed 检查/close() 无法取消已排队任务；`connect()` 不复查 enabled → 服务销毁后仍可能创建连接、订阅、顶号、泄漏定时线程。
- **修复**：`connect()` 入口加 `if (!enabled) return` + `if (client != null) return`（代际守卫）。
- [x] 已修复

### 三轮-2 [WARNING] evictOldTerminal 在 retry 窗口内淘汰刚重打的条目
- **文件**：`printer/PrintDispatcher.kt`
- **问题**：retry() 对 DONE 条目 gen++ 后 jobStatus 仍为 DONE、finishTime 旧值，直到新 dispatch 到达 setStatus(PRINTING)；期间其他任务终态触发淘汰过滤可能移除该条目 → nudge/cancel/retry 失效。
- **修复**：retry() 内立即 `jobStatus=QUEUED; finishTime=0` + persist，窗口内对淘汰过滤不可见。
- [x] 已修复

### 三轮-3 [SUGGESTION] retry PRINTING 守卫 TOCTOU
- **文件**：`printer/PrintDispatcher.kt`
- **问题**：volatile 读 jobStatus 与 dispatch 写 PRINTING 无同步，亚微秒窗口可双打印。
- **修复**：retry() 用 per-printer `Mutex.tryLock()` 包住检查+gen++（tryLock 失败即打印中）。
- [x] 已修复

### 三轮-4 [SUGGESTION] Raster 预缩放 th 奇数时非严格等价

### 三轮-5 [SUGGESTION] DNS rebinding TOCTOU

### 三轮-6 [SUGGESTION] IPv6 ULA/6to4/Teredo 未拦截

## 二轮审查（2026-07-31 修复后复查）——全部已修复

### 二轮-1 [CRITICAL] SSRF 防护被重定向绕过
- **文件**：`layout/LayoutGraphics.kt`
- **问题**：`validateImageHost` 只校验原始 URL，OkHttp 默认 `followRedirects=true`（含 HTTPS→HTTP 降级），重定向目标不重新校验 → 防护可被确定性绕过。
- **修复**：`followRedirects(false)` + `followSslRedirects(false)`（拒绝一切 3xx）。
- [x] 已修复

### 二轮-2 [WARNING] retry 后旧 gen 协程删掉新 gen 条目
- **文件**：`printer/PrintDispatcher.kt`
- **问题**：旧协程在检查点 `entries.remove` 把新代协程正在处理的条目删掉 → cancel 失效、nudge 找不到、wake 被旧协程消费。
- **修复**：3 处检查点只 `return` 不 remove；`retry()` 补 `wake.trySend`；`jobStatus` 加 `@Volatile`。
- [x] 已修复

### 二轮-3 [WARNING] CancellationException 被吞 → 关闭时任务标 FAILED 永不恢复
- **文件**：`printer/PrintDispatcher.kt`
- **问题**：兜底 `catch (e: Exception)` 捕获 `CancellationException`，服务关闭时在途任务被标 FAILED，`restoreAndResume` 只恢复 queued/printing/waiting → 永不续打。
- **修复**：兜底 catch 前加 `catch (e: CancellationException) { throw e }`（留 PRINTING 供重启恢复）。
- [x] 已修复

### 二轮-4 [WARNING] initAll 僵尸化
- **文件**：`service/PrintService.kt`
- **问题**：`initAll()` 是阻塞函数不可取消，onDestroy 期间继续执行 → 僵尸 MQTT/监测（重启顶号循环）。
- **修复**：`@Volatile destroyed` 标志，initAll 各阶段（配置后/队列后/恢复后/启动后）检查并清理已建资源。
- [x] 已修复

### 二轮-5 [WARNING] onJobEvent 访问未初始化 mqtt
- **文件**：`service/PrintService.kt`
- **问题**：`restoreAndResume` 先于 `mqtt` 赋值启动协程，恢复任务快速完成时 `UninitializedPropertyAccessException`，回执丢失。
- **修复**：`mqtt` 赋值移到 `restoreAndResume` 之前 + `if (::mqtt.isInitialized)` 守卫。
- [x] 已修复

### 二轮-6 [WARNING] 终态条目无上限增长
- **文件**：`printer/PrintDispatcher.kt`
- **问题**：保留终态任务后唯一清除路径是 cancel/clearDone，常驻服务内存无界增长（每个 Entry 持有 payload+sourceJson）。
- **修复**：`MAX_TERMINAL_ENTRIES=200`，setStatus 终态时按 finishTime 淘汰最旧。
- [x] 已修复

### 二轮-7 [WARNING] Logger SimpleDateFormat 线程不安全

- **问题**：时间戳在调用线程（MQTT 回调/IO 协程/主线程）并发格式化，损坏时间戳甚至抛异常打崩调用方。

## 🔴 CRITICAL（致命，必须修）

### 1. 死锁：连接失败后整台打印机队列永久卡死
- **文件**：`app/src/main/java/com/congmingpay/android/printer/PrintDispatcher.kt:196`
- **问题**：`kotlinx.coroutines.sync.Mutex` 不可重入。`catch (ConnectException)` 分支在 `lock.withLock {}`（174行）内部又调 `lock.withLock {}`（196行）锁同一把锁——协程永久等不到自己已持有的锁，外层 `withLock` 永不返回，该打印机锁永不释放，此后该机所有任务永久阻塞。
- **修复方向**：删除 196 行；外层 `withLock` 返回时自然释放锁。
- [x] 已修复（2026-07-31：删除嵌套 withLock，成功/失败分支统一由外层 withLock 释放）

### 2. 已完成任务被立即删除，重印/历史/预览全失效
- **文件**：`app/src/main/java/com/congmingpay/android/printer/PrintDispatcher.kt:188-192`
- **问题**：打印成功后 `entries.remove` + `store.deleteJob`。Windows 端成功任务保留，仅「清除已完成」或超期历史清理删除。当前导致无法预览/重打、`JobHistoryDays` 形同虚设。
- **修复方向**：成功时保留任务（落库 DONE + 留在内存），仅 `clearDone()`/历史清理删除。
- [x] 已修复（2026-07-31：成功分支只 setStatus(DONE)，不再 remove/delete；取消仍 DELETE）

## 🟠 WARNING（重要）

### 3. 「重新打印」缺少"打印中拒绝"守卫 → 可能重复出纸
- **文件**：`app/src/main/java/com/congmingpay/android/printer/PrintDispatcher.kt:275-284`
- **问题**：Windows 端「打印中」拒绝重打。Android `retry()` 只 `gen++`，若任务正在打印，新协程等锁释放后再次打印 → 多打一张。
- **修复方向**：`retry()` 里若 `jobStatus == PRINTING` 直接返回。
- [x] 已修复（2026-07-31：retry() 加 PRINTING 守卫）

### 4. 蜂鸣字节与 Windows 不一致
- **文件**：`app/src/main/java/com/congmingpay/android/printer/PrintDispatcher.kt:137`
- **问题**：Android `Buzzer.buildBuzzer(3, 2)` 输出 `1B 42 03 02`（100ms）；Windows `BuildBuzzer(3, 3)` 输出 `1B 42 03 03`（150ms）。同一输入两端字节不同。
- **修复方向**：改成 `Buzzer.buildBuzzer(3, 3)`。
- [x] 已修复（2026-07-31：改为 (3,3)，两端输出一致 `1B 42 03 03`）

### 5. 云端凭据明文存储 + 允许备份 → 密钥可被窃取
- **文件**：`app/src/main/java/com/congmingpay/android/config/ConfigManager.kt:72` + `app/src/main/AndroidManifest.xml:33`
- **问题**：`config.json` 明文存 MQTT 密码、阿里云 `accessKey`/`secretKey`、物联网 `deviceSecret`；Manifest `allowBackup="true"` 无排除规则，备份/rooted 设备可提取。
- **修复方向**：`allowBackup="false"`（或 `dataExtractionRules` 排除 config.json）；密钥 Keystore 加密存储。
- [x] 已修复（2026-07-31：allowBackup="false"；Keystore 加密留待后续增强）

### 6. 图片下载无校验 → 可被恶意推送触发 SSRF/内存崩溃
- **文件**：`app/src/main/java/com/congmingpay/android/layout/LayoutGraphics.kt:137`
- **问题**：打印消息 `png` 元素可指向元数据/内网地址或超大/解压炸弹图片。跟随重定向、无大小上限、无界 base64/`BitmapFactory` 解码。恶意发布者可 SSRF 内网或打崩常驻前台服务。

- [x] 已修复（2026-07-31：仅 https/data、2MB 数据上限、2048px 像素上限、拒绝私网/环回/链路本地地址、限流读取）

- **修复方向**：DAO 访问改 suspend，或在 `startForeground` 前用后台协程初始化。

### 8. 重启恢复 + 历史清理从未接线 → 功能缺口
