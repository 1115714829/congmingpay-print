票据打印服务器 · API 接口文档

面向餐厅厨房的热敏小票打印服务器。云端下发指令，本地服务执行，通过 USB 或网口打印。

本页仅供接口文档查看，为只读页面。数据通信通过 MQTT 完成，本服务不提供打印或数据接口。

一、通信方式

云端与本服务之间的唯一通道为 MQTT（MQTT 3.1.1）。本服务作为客户端连接指定的 broker，订阅短商户号主题以接收打印消息，并向 <短商户号>/report 主题发布打印回执与在线状态。

  • 连接：Broker 地址与端口（默认 1883），用户名与密码，明文传输。
  • 消息质量等级：QoS 1。
  • 断线自动重连；异常断开时由 broker 代发遗嘱消息（LWT），内容为离线状态。
  • 短商户号仅允许字母、数字与下划线，其余字符在输入时自动去除。

主题

方向主题内容
下行（订阅）<短商户号>打印消息，为单个 JSON 对象或对象数组
上行（发布）<短商户号>/report打印回执（type=ack）与在线状态（type=status）

二、打印消息（PrintRequest）

消息 payload 为一个打印请求对象，或一个打印请求对象数组。数组中的每个元素为一个独立的打印请求，各自处理，互不影响。收到的每一条消息都会处理并打印。

字段

字段类型必填默认说明
printer字符串 或 对象与 gateway 二选一—打印目标。字符串表示已注册打印机的名称或 ID；对象为 {name, ip, brand, width}
gateway字符串与 printer 二选一—网口 IP（如 192.168.68.194），或 "usb" 表示首台已注册 USB 打印机
id整数可选0请求标识，仅用于回执与日志对应，不用于去重
type整数可选5内容类型。见下文「内容类型」
pWidth整数可选按打印机设置纸张宽度（毫米），取值 58 或 80
pCopy整数可选1打印份数
contents数组 或 字符串可选—打印内容。type=5 时为排版元素数组；type=1 时为 base64 字符串
buzzer整数必填—蜂鸣：0 关闭，1 开启
cut整数必填—切刀：0 不切纸，1 切纸
reprint整数必填—重打提示标题：0 普通，1 在小票顶部添加「重打」标题
headLines整数必填—首部空行数，0 表示默认
tailLines整数必填—尾部空行数，0 表示默认

必填字段（buzzer / cut / reprint / headLines / tailLines）对所有内容类型均适用。缺失任一字段，或 buzzer / cut / reprint 取值非 0 或 1，请求将被拒绝，回执 ok 为 false，不应用默认值。

内容类型（type）

取值contents 形式处理方式
不填 或 0 或 5排版元素数组由服务端渲染为 ESC/POS 指令，包含编码、排版与纸宽自适应
1base64 字符串解码后作为原始 ESC/POS 指令直接下发，服务端不再排版

两种类型的字节均由服务端统一收尾（蜂鸣、首尾空行、按 cut 切纸），因此 type=1 的 base64 内容无需包含切纸或走纸指令。

打印目标解析

  • 网口 IP：printer.ip 或 gateway 为 IP。若该 IP 未注册，将在打印时自动登记为新的打印机；端口默认 9100。
  • USB：gateway 为 "usb"，或 printer 指定 USB 驱动名。选择已注册的 USB 打印机，不自动登记。
  • 名称或 ID：printer 为字符串。仅在已注册打印机中查找，未找到则返回错误。

下发报文中的五个必填参数与 printer 身份字段（name、brand、width）将覆盖并持久化至目标打印机配置。

三、排版元素（type=5）

contents 为排版元素数组，服务端按元素顺序渲染为 ESC/POS，并按纸张宽度自适应（58mm 为 32 字符，80mm 为 48 字符）。支持的元素类型如下。

元素（type）说明
title标题，居中加粗
text（默认）文本。支持 bold（加粗）、size（两位数字，宽与高放大倍率，取值 0 至 7）、align（left、center、right）。内容为空时输出空行
div_line / div_star分割线（- 或 *），可附带居中标题
表格由 thead（对象或数组，列宽百分比）与 tbody（二维数组）构成，按列宽自动换行
both_sides左右两段文本，分别左对齐与右对齐
qrcode二维码，支持单码与双码
bc128 / code39一维条码（Code128、Code39），可附带 HRI 文本
png图片，来源为 URL 或 base64，转为单色位图
cut切纸元素在渲染时被忽略，切纸由报文顶层 cut 字段统一控制

四、上行消息（发布至 <短商户号>/report）

打印回执（ack）

每条打印请求处理后发布一条回执。

{"type":"ack","id":6812801,"ok":true,"jobNo":1001,"message":"已提交"}
字段说明
type固定为 "ack"
id对应请求的 id
ok是否受理成功
jobNo任务号，ok 为 true 时返回
message结果说明或失败原因

在线状态（status）

连接并订阅成功后发布上线状态；主动退出或异常断开（遗嘱）时发布离线状态。

{"type":"status","event":"online","ts":1720000000000}
{"type":"status","event":"offline"}

五、打印与队列行为

打印任务进入队列后，按连接方式分为网口与 USB 两条独立路径。

网口打印

  • 派发前先通过 ICMP 探测判断是否在线；离线则进入等待队列。状态探测不使用打印端口 9100。
  • 实际打印结果为最终判据。打印口被占用或未就绪（连接被拒绝）时，任务进入等待队列并按 1 至 3 秒退避重试，占用释放后自动打印。
  • 网络超时或不可达时，任务进入等待队列并按 5 至 30 秒退避重试，恢复连接后自动打印。
  • 已连接但写入失败时，任务标记为失败，不自动重试。
  • 每台打印机使用一把打印串行锁，同一时刻仅建立一个连接；多份或并发任务串行打印。空闲无任务时不接触端口 9100。
  • 连接被拒绝持续约 20 秒后，在打印队列的详情列与日志中显示警告（端口可能未就绪或打印机故障），任务保持等待，不自动失败。

USB 打印

  • USB 打印通过 Windows 打印后台（打印驱动）完成，不进行 ICMP 在线探测，不接触端口 9100，不参与被占用或离线的重试逻辑。
  • 成功交付打印后台即视为完成（打印机离线时，Windows 会在其恢复后补打）；交付失败（驱动、名称或配置错误）即标记为失败。

重打

「重打」提示标题由两种方式触发：在打印队列中点击「重新打印」，或下发报文 reprint 为 1。两种方式均会在小票顶部添加「重打」标题，并遵循上述队列规则。reprint 为 0 的普通打印不显示该标题。

六、示例

单台（网口 IP，未注册时自动登记）

{
  "printer": {"name":"飞蛾1","ip":"192.168.68.194","brand":"飞蛾","width":80},
  "id": 6812801,
  "type": 5,
  "pWidth": 80,
  "pCopy": 1,
  "buzzer": 1, "cut": 1, "reprint": 0, "headLines": 0, "tailLines": 0,
  "contents": [
    {"cont":"结账单","type":"title"},
    {"cont":"【堂食】桌号：A08","type":"text","align":"center"},
    {"type":"div_line"},
    {"thead":{"商品名称":"85%","数量":"15%"},"tbody":[["猪肉大葱小笼包","1笼"]]},
    {"type":"div_line"},
    {"cont":"总计：1件","type":"text","bold":true,"align":"right"}
  ]
}

多台（数组，一次下发多条）

最外层为数组 [ {…}, {…} ]，每个元素结构同上，各自指定 printer 或 gateway 与内容。数组中多个元素指向同一台打印机时，该打印机按顺序依次打印。
